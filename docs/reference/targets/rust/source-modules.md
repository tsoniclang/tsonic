## `@tsonic/rust/lang.js`

| Export | Meaning |
| --- | --- |
| `ref<T, L>(value)` | Form one exact shared native reference |
| `mut<T, L>(value)` | Form one exact mutable native reference |
| `load(reference)` | Read through an exact native reference |
| `store(reference, value)` | Write through an exact mutable native reference |
| `range<T>(start, end)` | Exclusive native range `start..end` |
| `propagate(result)` | Native `?` inside a `Result`-returning function |

Portable ownership markers such as `sharedBorrow`, `mutableBorrow`, and
`move`, safe typed locations, native-pointer operations, `unsafeContext`, and
the safety builder remain owned by `@tsonic/core/*`. The Rust modules above
exist only for semantic controls that are intrinsically Rust-specific.

All listed modules are compiler-owned virtual declarations, not npm packages.

## Native macros

Import vector constructors from `@tsonic/rust/std/vec.js` or
`@tsonic/rust/alloc/vec.js`. They produce the provider's native `Vec<T>`:

```ts
import { vec, vecRepeat } from "@tsonic/rust/std/vec.js";
import type { int32 } from "@tsonic/core/types.js";

const values = vec<int32>(1, 2, 3);
const copies = vecRepeat<int32>(7, 4);
```

The output uses `vec![1, 2, 3]` and `vec![7; 4]`. Repetition follows native
Rust evaluation and `Clone` requirements, including when the count is zero.

`println` and `eprintln` come from `@tsonic/rust/std/index.js`. The format must
be a literal and every value must be an explicit argument:

```ts
import { println } from "@tsonic/rust/std/index.js";

println("{} elements", values.len());
```

Rust checks the formatting traits and format specifiers. Implicit captures
such as `"{values}"` are rejected: those names are not checked source arguments.
No JavaScript argument array or eagerly formatted String is introduced.

## Attributes

Use the shared attribute selector with one checked invocation:

```ts
import { attribute } from "@tsonic/core/lang.js";
import { nativeAttribute } from "@example/native-attributes";

attribute<typeof work>().add(() => nativeAttribute(4));
```

The imported provider must declare the exact native attribute, argument schema
and permitted placements. `attribute.module().add(() => moduleAttribute())`
selects the current source module and emits its body inline. Helper attributes
may require a particular module attribute. Derives use the same checked API.
The lambda is compile-time input, not an emitted runtime callable.
Tuple and record arguments must be literals. Scalar `const` aliases are allowed;
an array or object stored in a `const` binding can still be mutated and is not
treated as compile-time metadata.

This does not discover arbitrary APIs generated by a procedural macro. A
consumer needs an exact provider declaration before source checking. Tsonic
does not infer generated exports from names or printed Rust.
